# Обработки 1С

В каталоге `src/` лежат **исходные тексты модулей объекта** двух внешних обработок.
Поскольку файл `.epf` бинарный (и его нельзя осмысленно хранить/ревьюить в git),
здесь хранится именно код, а сама обработка собирается на стороне 1С.

| Файл                                   | Назначение                                              |
|----------------------------------------|---------------------------------------------------------|
| `src/ВыгрузкаСтруктурыМетаданных.bsl`  | ① Выгрузка структуры метаданных любой КФ → `.1cmeta`    |
| `src/ВыгрузкаДанныхПоСхеме.bsl`        | ③ Выгрузка данных по отредактированной схеме → `.1cdata`|
| `src/ОблачныеПриёмники.bsl`            | Прямая отправка данных из 1С в S3 / ClickHouse / YDB    |
| `src/ВыгрузкаСтруктурыМетаданных_МодульФормы.bsl` | Код модуля формы для обработки ①              |
| `src/ВыгрузкаДанныхПоСхеме_МодульФормы.bsl`       | Код модуля формы для обработки ③              |

Совместимы с управляемым приложением 1С:Предприятие 8.3.

## Как собрать внешнюю обработку

1. В Конфигураторе (или EDT): **Файл → Новый → Внешняя обработка**, задайте имя
   (`ВыгрузкаСтруктурыМетаданных` / `ВыгрузкаДанныхПоСхеме`).
2. Откройте **Модуль объекта** обработки и вставьте содержимое соответствующего
   `.bsl`.
3. Добавьте управляемую форму. Состав формы (реквизиты, элементы, команды) и
   готовый код модуля формы — в файлах `*_МодульФормы.bsl`: создайте реквизиты и
   элементы по таблицам в шапке файла, затем вставьте код в модуль формы.
   Для чисто программного использования форма не нужна.
4. Сохраните `.epf`.

> Альтернатива: собрать `.epf` из исходников утилитой OneScript/`gitsync`/EDT, если
> у вас настроена выгрузка обработок в исходники.

## ① Выгрузка структуры метаданных

Экспортный метод модуля объекта:

```bsl
// ПутьКФайлу — куда писать .1cmeta
Результат = ВыгрузитьСтруктуруВФайл("C:\temp\erp.1cmeta");
Сообщить("Узлов: " + Результат.КоличествоУзлов);
```

Необязательные настройки (вторым параметром — `Структура`):

* `ВыгружатьОтчетыОбработки` (Булево) — включать Отчёты/Обработки. По умолчанию `Ложь`.
* `ВыгружатьКоманды` (Булево).
* `ТолькоОбъектыСДанными` (Булево).

Пример обработчика кнопки на форме (клиент + сервер):

```bsl
&НаКлиенте
Процедура Выгрузить(Команда)
    Диалог = Новый ДиалогВыбораФайла(РежимДиалогаВыбораФайла.Сохранение);
    Диалог.Расширение = "1cmeta";
    Если Диалог.Выбрать() Тогда
        ВыгрузитьНаСервере(Диалог.ПолноеИмяФайла);
    КонецЕсли;
КонецПроцедуры

&НаСервере
Процедура ВыгрузитьНаСервере(Путь)
    РеквизитФормыВЗначение("Объект").ВыгрузитьСтруктуруВФайл(Путь);
КонецПроцедуры
```

> Файл пишется на той стороне, где выполняется метод (в примере — на сервере).
> Для файловой базы это рабочий каталог; для клиент-серверной — каталог сервера,
> затем файл можно получить через `ПоместитьФайл`.

## ③ Выгрузка данных по схеме

```bsl
Параметры = РеквизитФормыВЗначение("Объект").ПараметрыВыгрузкиПоУмолчанию();
Параметры.ДатаНачала     = '20260101';
Параметры.ДатаОкончания  = '20260331';
Параметры.Организация    = Справочники.Организации.НайтиПоНаименованию("ООО Ромашка").Ссылка;
Параметры.РежимРазбиения = "objects+volumes"; // single | objects | volumes | objects+volumes
Параметры.МаксСтрокВТоме = 100000;
Параметры.ПорцияСервера  = 10000;

Результат = ВыгрузитьДанные(
    "C:\temp\erp_edited.1cmeta",  // отредактированная в GUI схема
    "C:\temp\out\erp.1cdata",     // базовое имя/каталог для выходных файлов
    Параметры);

Сообщить("Строк: " + Результат.Строк + ", файлов: " + Результат.Файлы.Количество());
```

### Чанкинг серверных вызовов и `rphost`

Каждая порция данных читается **отдельным запросом** `ВЫБРАТЬ ПЕРВЫЕ N … ГДЕ
Ссылка > &Курсор` (keyset-пагинация по ссылке), поэтому ни один запрос не выбирает
больше `ПорцияСервера` записей — это удерживает память `rphost` в рамках.

Для тонкого клиента, чтобы каждая порция стала отдельным серверным вызовом,
вынесите чтение порции в `&НаСервереБезКонтекста`-функцию формы и вызывайте её в
цикле с клиента (метод `ПрочитатьПорцию` для этого помечен экспортным). При
серверном запуске встроенной обработки этого не требуется: ограничение памяти
обеспечивается размером порции в каждом запросе.

### Режимы разбиения файлов

| Режим             | Результат                                                        |
|-------------------|------------------------------------------------------------------|
| `single`          | всё в одном файле                                                |
| `objects`         | отдельный файл на каждый объект метаданных                       |
| `volumes`         | многотомно по `МаксСтрокВТоме`                                   |
| `objects+volumes` | для каждого объекта — свой набор томов                           |

Галки комбинируются: можно выгружать огромные базы, нарезая и по объектам, и по
томам одновременно.

## Прямая выгрузка из 1С в облако (опционально)

Промежуточный файл `.1cdata` пишется **всегда** — это базовый и самый надёжный
путь. Дополнительно можно включить прямые приёмники Yandex Cloud, и тогда строки
уходят в облако в процессе выгрузки (батчами), без ручной загрузки файла.

### Установка

Поместите содержимое `src/ОблачныеПриёмники.bsl` в **общий модуль** конфигурации
с именем `ОблачныеПриёмники` (флаги: Сервер, Внешнее соединение). Обработка
`ВыгрузкаДанныхПоСхеме` вызывает его как `ОблачныеПриёмники.<Метод>`.
Для внешней обработки без конфигурации — вставьте обе части в один модуль объекта
и уберите префикс `ОблачныеПриёмники.` в вызовах.

На сервере 1С должен быть доступен корневой сертификат Yandex
(`YandexInternalRootCA.crt`) — либо укажите путь к нему в поле `CACert`.

### Пример

```bsl
Параметры = РеквизитФормыВЗначение("Объект").ПараметрыВыгрузкиПоУмолчанию();
Параметры.ДатаНачала    = '20260101';
Параметры.ДатаОкончания = '20260331';

// Архив + Object Storage
Параметры.Облако.S3.Включить  = Истина;
Параметры.Облако.S3.Бакет     = "my-1c-bucket";
Параметры.Облако.S3.AccessKey = "YCAJE...";
Параметры.Облако.S3.SecretKey = "YCxxx...";
Параметры.Облако.S3.CACert    = "C:\certs\YandexInternalRootCA.crt";

// Прямая вставка в Managed ClickHouse
Параметры.Облако.ClickHouse.Включить    = Истина;
Параметры.Облако.ClickHouse.Хост        = "rc1a-xxxx.mdb.yandexcloud.net";
Параметры.Облако.ClickHouse.База         = "onec";
Параметры.Облако.ClickHouse.Пользователь = "admin";
Параметры.Облако.ClickHouse.Пароль       = "***";
Параметры.Облако.ClickHouse.CACert       = "C:\certs\YandexInternalRootCA.crt";

Результат = ВыгрузитьДанные("erp_edited.1cmeta", "C:\out\erp.1cdata", Параметры);
```

### Как это работает

* **S3 (Object Storage).** После записи файлов они (опц. сначала упаковываются в
  zip) загружаются PUT-запросом с подписью **AWS Signature V4** (HMAC-SHA256
  реализован в модуле на `ХешированиеДанных`).
* **ClickHouse.** Строки буферизуются по объекту и батчами отправляются HTTPS
  POST'ом в формате `JSONEachRow` (по умолчанию 1000 строк на вызов). Имена
  таблиц/колонок и раскладка ссылок (`id` + `_view`) совпадают с DDL,
  генерируемым GUI-редактором.
* **YDB.** Прямая вставка из 1С идёт через **Document API** (DynamoDB-совместимый,
  `BatchWriteItem`, до 25 строк на вызов), т.к. реляционные таблицы YDB
  наполняются только по gRPC (из 1С по HTTP недоступно). Для реляционной схемы
  используйте путь S3 → импорт либо Python-загрузчик редактора.

> Раскладка колонок (транслитерация, `id`+`_view`, составные → JSON) единообразна
> с генератором DDL и Python-загрузчиком — таблицы и данные согласованы.

### Создание таблиц и сверка структуры

Разделение ответственности:

* **Таблицы создаёт GUI-редактор** — он единственный владелец DDL: генерирует и
  применяет `CREATE TABLE` для MariaDB / ClickHouse / YDB (меню «Экспорт → DDL…»
  и кнопка «Создать таблицы» в окне «Интеграции»).
* **1С перед прямой выгрузкой только СВЕРЯЕТ структуру** целевых таблиц со схемой
  и прерывает выгрузку с понятной ошибкой, если что-то не совпало — чтобы не
  начать лить данные в «не ту» таблицу.

Сверка включена по умолчанию (`Параметры.Облако.СверятьПередВыгрузкой = Истина`)
и срабатывает для включённых HTTP-приёмников:

* **ClickHouse** — читает `system.columns` и проверяет наличие всех ожидаемых
  колонок (включая `*_view` и JSON-колонки составных типов).
* **YDB** — через `DescribeTable` проверяет наличие таблицы и ключевых атрибутов
  (`Ссылка`, `НомерСтроки`). Неключевые атрибуты в DocAPI не описаны — для них
  проверяется только существование таблицы.
* **MariaDB** — из 1С недостижима по HTTP, поэтому не сверяется: создавайте и
  проверяйте её таблицы в редакторе.

Ручной вызов сверки (без выгрузки) — метод `СверитьСхему(ПутьСхемы, Параметры)`
или кнопка **«Сверить схему с БД»** на форме:

```bsl
Сверка = Объект.СверитьСхему("erp_edited.1cmeta", Параметры);
Если НЕ Сверка.Ок Тогда
    Для Каждого Проблема Из Сверка.Проблемы Цикл
        Сообщить(Проблема);
    КонецЦикла;
КонецЕсли;
```

> ⚠️ BSL-приёмники написаны под платформу 8.3, но в этом окружении не выполнялись
> на живой базе/облаке. Перед продакшеном протестируйте на тестовом контуре
> (особенно подпись SigV4 и установку сертификата YC).

## Сервисные функции (без выгрузки)

На форме выгрузки данных есть кнопки самопроверки и статистики — все «лёгкие»,
без побочных эффектов:

* **Сверить схему с БД** — `СверитьСхему(ПутьСхемы, Параметры)`: проверяет, что
  структура таблиц ClickHouse/YDB соответствует схеме (см. раздел выше). Та же
  сверка выполняется автоматически перед прямой выгрузкой в облако.
* **Проверить ClickHouse / S3 / YDB** — быстрый тест подключения и учётных данных:
  `ОблачныеПриёмники.ПроверитьClickHouse` (`SELECT version()`),
  `ПроверитьS3` (GET бакета `?max-keys=0`, SigV4),
  `ПроверитьYDB` (`ListTables`). Возвращают строку статуса или текст ошибки.
  Дополнительно есть `ТаблицаСуществуетВClickHouse(Конфиг, ИмяТаблицы)`.
* **Оценить объёмы** — `ВыгрузитьДанные`-обработка, метод `ОценитьОбъёмы(ПутьСхемы,
  Параметры)`: по одному запросу `КОЛИЧЕСТВО(*)` на объект (с учётом периода/
  организации/подразделения) — прогноз числа записей и итог перед выгрузкой.
* **Сводка схемы** — метод `СводкаСхемы(ПутьСхемы)`: сколько объектов, полей и
  табличных частей будет выгружено и разбивка по видам, без обращения к данным.

Пример программного вызова:

```bsl
Объект = РеквизитФормыВЗначение("Объект"); // или внешняя обработка
Оценка = Объект.ОценитьОбъёмы("erp_edited.1cmeta", Параметры);
Сообщить("Всего записей к выгрузке: " + Оценка.Итого);

Статус = ОблачныеПриёмники.ПроверитьClickHouse(Параметры.Облако.ClickHouse);
Сообщить(Статус);
```

### Ещё что можно добавить сервисного (идеи)

* Сверка структуры целевой таблицы ClickHouse со схемой (наличие колонок/типов).
* «Сухой прогон» выгрузки в файл-заглушку для проверки запросов и прав без записи.
* Проверка свободного места в каталоге выгрузки перед стартом.
* Журналирование запусков (регистр сведений: когда, кто, объём, длительность).
* Проверка наличия и срока действия сертификата YC (CACert).
* Хранение секретов в YC Lockbox вместо полей формы.

## Программный запуск из конфигурации

Обе обработки можно встроить в конфигурацию (как встроенную обработку) и вызывать
их экспортные методы из любого серверного кода — например, по расписанию
регламентного задания. Интерактивная форма при этом не обязательна.
