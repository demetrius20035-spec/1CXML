# Обработки 1С

В каталоге `src/` лежат **исходные тексты модулей объекта** двух внешних обработок.
Поскольку файл `.epf` бинарный (и его нельзя осмысленно хранить/ревьюить в git),
здесь хранится именно код, а сама обработка собирается на стороне 1С.

| Файл                                   | Назначение                                              |
|----------------------------------------|---------------------------------------------------------|
| `src/ВыгрузкаСтруктурыМетаданных.bsl`  | ① Выгрузка структуры метаданных любой КФ → `.1cmeta`    |
| `src/ВыгрузкаДанныхПоСхеме.bsl`        | ③ Выгрузка данных по отредактированной схеме → `.1cdata`|

Совместимы с управляемым приложением 1С:Предприятие 8.3.

## Как собрать внешнюю обработку

1. В Конфигураторе (или EDT): **Файл → Новый → Внешняя обработка**, задайте имя
   (`ВыгрузкаСтруктурыМетаданных` / `ВыгрузкаДанныхПоСхеме`).
2. Откройте **Модуль объекта** обработки и вставьте содержимое соответствующего
   `.bsl`.
3. Добавьте простую управляемую форму с кнопками (см. ниже) — для интерактивного
   запуска. Для чисто программного использования форма не нужна.
4. Сохраните `.epf`.

> Альтернатива: собрать `.epf` из исходников утилитой OneScript/`gitsync`/EDT, если
> у вас настроена выгрузка обработок в исходники.

## ① Выгрузка структуры метаданных

Экспортный метод модуля объекта:

```bsl
// ПутьКФайлу — куда писать .1cmeta
Результат = ВыгрузитьСтруктуруВФайл("C:\temp\erp.1cmeta");
Сообщить("Узлов: " + Результат.КоличествоУзлов);
```

Необязательные настройки (вторым параметром — `Структура`):

* `ВыгружатьОтчетыОбработки` (Булево) — включать Отчёты/Обработки. По умолчанию `Ложь`.
* `ВыгружатьКоманды` (Булево).
* `ТолькоОбъектыСДанными` (Булево).

Пример обработчика кнопки на форме (клиент + сервер):

```bsl
&НаКлиенте
Процедура Выгрузить(Команда)
    Диалог = Новый ДиалогВыбораФайла(РежимДиалогаВыбораФайла.Сохранение);
    Диалог.Расширение = "1cmeta";
    Если Диалог.Выбрать() Тогда
        ВыгрузитьНаСервере(Диалог.ПолноеИмяФайла);
    КонецЕсли;
КонецПроцедуры

&НаСервере
Процедура ВыгрузитьНаСервере(Путь)
    РеквизитФормыВЗначение("Объект").ВыгрузитьСтруктуруВФайл(Путь);
КонецПроцедуры
```

> Файл пишется на той стороне, где выполняется метод (в примере — на сервере).
> Для файловой базы это рабочий каталог; для клиент-серверной — каталог сервера,
> затем файл можно получить через `ПоместитьФайл`.

## ③ Выгрузка данных по схеме

```bsl
Параметры = РеквизитФормыВЗначение("Объект").ПараметрыВыгрузкиПоУмолчанию();
Параметры.ДатаНачала     = '20260101';
Параметры.ДатаОкончания  = '20260331';
Параметры.Организация    = Справочники.Организации.НайтиПоНаименованию("ООО Ромашка").Ссылка;
Параметры.РежимРазбиения = "objects+volumes"; // single | objects | volumes | objects+volumes
Параметры.МаксСтрокВТоме = 100000;
Параметры.ПорцияСервера  = 10000;

Результат = ВыгрузитьДанные(
    "C:\temp\erp_edited.1cmeta",  // отредактированная в GUI схема
    "C:\temp\out\erp.1cdata",     // базовое имя/каталог для выходных файлов
    Параметры);

Сообщить("Строк: " + Результат.Строк + ", файлов: " + Результат.Файлы.Количество());
```

### Чанкинг серверных вызовов и `rphost`

Каждая порция данных читается **отдельным запросом** `ВЫБРАТЬ ПЕРВЫЕ N … ГДЕ
Ссылка > &Курсор` (keyset-пагинация по ссылке), поэтому ни один запрос не выбирает
больше `ПорцияСервера` записей — это удерживает память `rphost` в рамках.

Для тонкого клиента, чтобы каждая порция стала отдельным серверным вызовом,
вынесите чтение порции в `&НаСервереБезКонтекста`-функцию формы и вызывайте её в
цикле с клиента (метод `ПрочитатьПорцию` для этого помечен экспортным). При
серверном запуске встроенной обработки этого не требуется: ограничение памяти
обеспечивается размером порции в каждом запросе.

### Режимы разбиения файлов

| Режим             | Результат                                                        |
|-------------------|------------------------------------------------------------------|
| `single`          | всё в одном файле                                                |
| `objects`         | отдельный файл на каждый объект метаданных                       |
| `volumes`         | многотомно по `МаксСтрокВТоме`                                   |
| `objects+volumes` | для каждого объекта — свой набор томов                           |

Галки комбинируются: можно выгружать огромные базы, нарезая и по объектам, и по
томам одновременно.

## Программный запуск из конфигурации

Обе обработки можно встроить в конфигурацию (как встроенную обработку) и вызывать
их экспортные методы из любого серверного кода — например, по расписанию
регламентного задания. Интерактивная форма при этом не обязательна.
