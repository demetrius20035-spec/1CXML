# GUI-редактор схемы `.1cmeta`

Десктоп-редактор структуры метаданных 1С на Python + PySide6 (Qt).

## Установка и запуск

```bash
cd editor
python -m pip install -r requirements.txt          # PySide6
python -m onec_schema_editor ../examples/sample.1cmeta
```

или через установку пакета:

```bash
python -m pip install -e .
onec-schema-editor ../examples/sample.1cmeta
```

> Для запуска GUI нужны системные библиотеки Qt (на headless-Linux:
> `libegl1 libgl1 libxkbcommon0 libdbus-1-3`).

## Тесты

Логика модели/операций покрыта тестами и не требует GUI:

```bash
python -m pytest tests -q
```

## Архитектура

| Модуль            | Ответственность                                                    |
|-------------------|--------------------------------------------------------------------|
| `model.py`        | Потоковая загрузка/сохранение NDJSON, дерево `SchemaNode`, метки типов |
| `tree_model.py`   | `QAbstractItemModel` для `QTreeView`: чекбоксы, колонки, цвета      |
| `operations.py`   | Статистика, поиск/замена, высушивание составных типов (чистая логика) |
| `importers.py`    | Импорт `.1cmeta` из XML-выгрузки конфигурации (без запуска 1С)      |
| `profiles.py`     | Профили выгрузки (пресеты галок + настройки)                       |
| `diff.py`         | Сравнение двух схем                                                |
| `validate.py`     | Валидатор ссылочной целостности                                   |
| `exporters.py`    | Паспорт конфигурации для LLM (Markdown/JSON)                       |
| `estimate.py`     | Оценка объёмов (ширина строки + факт из `.1cdata`)                 |
| `translit.py`     | Транслитерация имён 1С в SQL-идентификаторы                        |
| `sqlgen.py`       | Генерация DDL для MariaDB / ClickHouse / YDB                       |
| `datafile.py`     | Потоковое чтение файлов данных `.1cdata`                           |
| `rowmap.py`       | Сопоставление строк `.1cdata` колонкам таблиц                     |
| `backends/`       | Бэкенды загрузки: MariaDB, ClickHouse, YDB, S3 (драйверы опциональны) |
| `llm_export.py`   | Экспорт схемы в JSON Schema / Pydantic / SQLAlchemy / dbt, оценка токенов |
| `filters.py`      | Фильтр дерева и пометки проблемных узлов (бейджи)                  |
| `dbcompare.py`    | Сверка схемы с реальной БД и обратная инженерия каркаса            |
| `history.py`      | Undo/Redo (стек команд)                                           |
| `dialogs.py`      | Диалоги редактирования типа и высушивания                          |
| `ui_integrations.py` | Окно интеграций (вкладки СУБД/облака) с прогрессом и сверкой с БД |
| `ui_extra.py`     | Diff-окно, просмотрщик `.1cdata`, граф связей                     |
| `app.py`          | Главное окно, меню, доки, тулбар, фильтр, контекстное меню         |

## Возможности качества/удобства

* **Мультивыделение** (Ctrl/Shift) — массовые операции через контекстное меню:
  отметить/снять, сменить вид, удалить набор узлов разом.
* **Undo/Redo** (`Ctrl+Z` / `Ctrl+Y`) — для галок, переименования, смены вида/типа,
  высушивания и удаления.
* **Фильтр дерева** (док слева): по тексту, «только отмеченные», «только составные»,
  «только висячие ссылки», «только объекты/поля данных» — с сохранением пути к
  совпадениям.
* **Бейджи проблем** прямо в дереве: фон светло-красный — висячая ссылка
  (`meta` на отсутствующий объект), светло-жёлтый — объект отмечен без полей;
  красный текст типа — составной.

## Экспорт для LLM / вайб-кодинга (меню «Экспорт»)

* **JSON Schema** (draft 2020-12), **Pydantic**, **SQLAlchemy ORM**, **dbt schema.yml**
  по отмеченному подмножеству. В статусбаре — оценка размера в токенах.

## Связь с реальной БД (меню «Интеграции»)

* **Сверить схему с БД** (MariaDB/ClickHouse) — интроспекция `information_schema`/
  `system.columns` и сравнение: нет таблиц/колонок (ошибки) и несовпадение типов
  (предупреждения).
* **Обратная инженерия** — `dbcompare.schema_from_db_tables` строит каркас `.1cmeta`
  из снимка таблиц БД (для ручной доводки).

`model.py`, `operations.py`, `importers.py`, `sqlgen.py`, `datafile.py`,
`rowmap.py`, `profiles.py`, `diff.py`, `validate.py`, `exporters.py`,
`estimate.py` не зависят от Qt — это библиотека для скриптовой обработки схем.

## Возможности (расширенные)

* **Импорт из Configuration.xml/EDT** — меню «Файл → Импорт из Configuration.xml…»:
  строит `.1cmeta` прямо из выгрузки конфигурации в файлы, без запуска 1С.
  Стандартные реквизиты синтезируются эвристически (в XML их нет).
* **Профили выгрузки** — сохранение/применение пресетов галок и настроек DDL.
* **Diff двух схем** — сравнение релизов: добавлено/удалено/сменился тип/вид.
* **Валидатор ссылочной целостности** — находит ссылки на отсутствующие объекты.
* **Паспорт для LLM** — компактный Markdown/JSON только отмеченного.
* **Оценка объёмов** — прогноз размера по схеме и факту `.1cdata`.
* **Просмотрщик `.1cdata`** — табличный предпросмотр выгрузки.
* **Граф связей** — круговая визуализация ссылочных связей объектов.
* **Генерация DDL** — `schema.sql` для MariaDB / ClickHouse / YDB
  (транслитерация имён и колонки `_view` переключаются в «Настройки SQL»).
* **Интеграции** — окно с вкладками: подключение, создание таблиц по DDL,
  загрузка `.1cdata` в СУБД с прогресс-баром; архивирование и выгрузка в S3.

## Опциональные драйверы интеграций

```bash
pip install -r requirements-integrations.txt   # всё сразу
# или точечно:
pip install PyMySQL              # MariaDB
pip install clickhouse-connect   # YC ClickHouse
pip install ydb                  # YC YDB
pip install boto3                # YC Object Storage (S3)
```

Редактор и все офлайн-функции работают и без этих пакетов — они нужны только
для вкладки «Интеграции».
